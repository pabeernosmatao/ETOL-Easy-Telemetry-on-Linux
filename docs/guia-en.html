01Getting started

ETOL is a single application: it detects your Steam simulators, prepares SimHub (and CrewChief if you want it) inside a Bottles bottle and launches everything with one click. It never modifies your games.

What you need

  • Linux x86_64 with glibc 2.39 or newer.
  • python3 (the telemetry bridges) and curl (downloads).
  • Steam with the games installed.
  • Bottles with a bottle that has SimHub. If you do not have one, ETOL creates and prepares it for you.
  • Optional: the HF8 pad and KDE Plasma for the dashboards above the game.

Opening the AppImage

chmod +x ETOL-0.3.19-linux-x86_64-portable.AppImage
./ETOL-0.3.19-linux-x86_64-portable.AppImage

The portable build uses the system WebKit and needs libwebkit2gtk-4.1 and libgtk-3. The full build bundles everything and needs glibc 2.44 or newer.

The first launch

On first start ETOL checks what is missing and shows a banner at the top:

Bottles Flatpak is missing

Click the banner and accept. ETOL installs Bottles for your user and gives it the minimum permissions (home, host-etc, Steam libraries and HF8).

The SimHub bottle is missing

ETOL downloads GE-Proton, creates the simhub bottle, installs the dependencies and opens the CrewChief and SimHub installers.

During installation a window opens with a progress bar and the current step: checking Bottles, downloading GE-Proton, creating the bottle, winetricks, CrewChief, SimHub… The Windows installers are interactive: click “Next” and uncheck what step 05 says.

03The Games tab

Each installed simulator has its own card. The data on the left tells you whether everything is ready:

  • Port: free, busy, or in use by the running bridge.
  • Prefix: the game's Proton prefix, or the plugin on native Linux games.
  • Launch: the lock ETOL uses to know the bridge is running.

The gear

The gear in the corner configures that game: copies plugins, adjusts SimHub, CrewChief and the bridges. It turns red when the game has never been configured or when ETOL sees something wrong (missing plugin, wrong SimHub mode…). Click it once per game; when it finishes, the gear is no longer red.

The buttons

  • Launch: starts the bridge and the game's apps. If it is already running, it becomes Stop.
  • CrewChief / SimHub: open or close only that application. The coloured dot shows whether it is running.
On games that only use SimHub (Euro Truck Simulator 2 and BeamNG.drive) the two buttons take half the width each: Launch and SimHub.

04Playing

Automatic watchdog (recommended)

With the watchdog on (Options → Automatic watchdog, enabled by default) you only have to open the simulator. ETOL detects it, starts its bridge and opens the selected apps. When you close the game it stops everything. If you switch games, it switches too.

Manual launch

If you prefer to control it yourself, disable the watchdog and use the card buttons or the tray menu. Launch does the same as the watchdog, but whenever you want.

ETOL must stay open to watch. You can leave it in the tray: closing the window keeps it in the background and the icon brings it back.

What happens when you quit

When you exit ETOL (tray → Quit, Alt+F4 or closing the window if there is no tray) it stops the bridges, closes the apps it opened and disables the KWin rule used by the dashboards.

05Bottles, SimHub and CrewChief from scratch

You do not need anything installed beforehand. If you accept the first screen's banners, ETOL does this whole stack:

  1. Installs Bottles as a user Flatpak if it is missing. It does not use sudo and does not touch the rest of the system.
  2. Creates the simhub bottle with a 64-bit Windows 11 prefix and a Proton runner (GE-Proton). If it already exists, it is reused.
  3. Prepares the prefix with dotnet48, vcrun2022, d3dcompiler_43, d3dx9 and corefonts through winetricks. It can take several minutes.
  4. Downloads and opens the installers: CrewChief (MSI) and SimHub (ZIP). They are Windows installers, so you have to click “Next”.
    In CrewChief, when it finishes do not check “Run CrewChiefV4”. In SimHub, uncheck Install .NET Runtime, Install USB Display Drivers and Install Visual C++ Redistributables, and do not run it at the end.

When it finishes, ETOL detects again and the game cards are ready to configure. If something fails, the diagnostics and logs say which step and why.

07Desktop: what works on each one

The application, detection, bridges and SimHub/CrewChief work on any desktop. What depends on the desktop are the dashboards above the game and the tray icon.

The dashboards over the game are a KWin rule that places the SimHub window above the simulator. On Plasma it works with or without gamescope; gamescope is not required. GNOME and niri do not implement that rule, so there ETOL provides telemetry and apps but no overlay.

On GNOME, without the “AppIndicator and KStatusNotifierItem Support” extension there is no tray: ETOL opens anyway and logs it. On niri, the icon is drawn by the bar (Waybar, Noctalia…); if the bar starts after ETOL, it retries registering for a minute.

ETOL also installs a group icon for SimHub and CrewChief (CrewChief on top, SimHub below) and its .desktop entry for the steam_proton window class, so the panel shows a single icon with both halves instead of the CrewChief icon. It is created on startup; nothing has to be run by hand.

08HF8 pad (optional)

The HF8 (ForceFeel) is a USB haptic pad. ETOL detects it, links its COM port inside the Bottles bottle and writes the keys SimHub needs. It is not mandatory: without it ETOL works the same and the diagnostics only show a warning.

In Devices you can enable or disable it, see the port and reconfigure it if you change USB.

09The tray

ETOL uses StatusNotifierItem (the Linux tray standard), so the icon is drawn by your desktop: Plasma natively, the niri bar if it has a tray module, or GNOME with the AppIndicator extension.

The icon menu has:

  • Show window (or left click on the icon).
  • One submenu per simulator with Launch and Stop everything.
  • Applications: open or close CrewChief and SimHub.
  • Quit: stops everything and closes ETOL.

If there is no tray host, ETOL opens anyway and logs it. In that case, closing the window quits the application (it does not stay hidden with no icon).

10Logs and diagnostics

In Diagnostics you have the checks with the fix next to them. In Options you can enable log capture and choose how many days to keep.

The logs live in ~/.config/etol/logs/:

  • etol-YYYY-MM-DD.log: app events.
  • setup-*.log and config-*.log: full output of installations and configurations.
  • run-YYYY-MM-DD/: copy of the bridge and SimHub/CrewChief logs.

If something fails, the most useful thing is to send the whole logs folder. The recoger-logs.sh script in the repository packs it into a .tar.gz.

11Common problems

No simulator appears

Check that Steam has them installed and click Detect again. ETOL reads all Steam libraries, including those on other disks, but it needs permission to access them.

The gear stays red

That game has not been configured or ETOL sees something wrong. Click the gear and read the result; the diagnostics show what is missing (plugin, SimHub mode, prefix…).

SimHub does not start

Check Applications and the diagnostics. If the bottle does not have SimHub, run the prefix preparation again.

There is no tray icon

Your desktop has no StatusNotifier host. On GNOME install the AppIndicator extension; on niri add a tray module to the bar. ETOL works the same without the icon.

The AppImage does not start

The portable build needs libwebkit2gtk-4.1 and libgtk-3. If your glibc is 2.44 or newer, try the full build. Without FUSE2: ./ETOL-*.AppImage --appimage-extract-and-run.

The dashboards do not appear above the game

That feature is exclusive to KDE Plasma (KWin rule). It is not available on GNOME or niri. On Plasma gamescope is not needed: it works with or without it.

I want to start over

Close ETOL and delete ~/.config/etol (configuration and payload). Bottles bottles and games are not touched. On the next start ETOL detects and prepares whatever is missing.
